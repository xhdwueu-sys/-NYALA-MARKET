# نيالا ماركت — Nyala Market

منصة إعلانات مبوبة لمدينة نيالا والسودان: البائع يعرض سلعته مع بيانات التواصل، والمشتري يتواصل مباشرة.

**نموذج العمل:** ليست متجراً إلكترونياً بسلة ودفع داخلي، بل منصة عرض + عمولة/رسوم على الإعلان.

## سياسة الرسوم (محدّثة)

| البند | التفاصيل |
|--------|----------|
| **أساس الرسوم** | حسب **القسم** + **نوع الإعلان** (عادي / مميز) |
| **العملة** | الجنيه السوداني (SDG) |
| **طرق الدفع** | **الاثنان معاً**: نقداً أو إلكتروني (تحويل بنكي / Bankak وغيره) |
| **التفعيل** | الإعلان يبقى `pending` حتى تأكيد الدفع من لوحة الإدارة (أو الإعفاء) |

### أمثلة رسوم أولية (قابلة للتعديل)

- إعلان عادي (افتراضي): **500 ج.س** / 30 يوم
- إعلان مميز (افتراضي): **1500 ج.س** / 30 يوم
- سيارات عادي: **1000 ج.س** | سيارات مميز: **3000 ج.س**
- عقارات عادي: **800 ج.س** | عقارات مميز: **2500 ج.س**

يتم تخزين القواعد في جدول `fee_rules` ويمكن تعديلها من قاعدة البيانات أو توسيع لوحة الإدارة لاحقاً.

## ما الذي يتضمنه المشروع؟

- واجهة عربية RTL متجاوبة (Next.js)
- تطبيق Android (Flutter)
- تصنيفات: المركبات، الإلكترونيات، المنزل، العقارات، الملابس، المعدات، الخدمات
- عرض وبحث أساسي + بلاغات + بائع موثّق
- لوحة إدارة: مراجعة إعلانات، **متابعة المدفوعات والرسوم**، بلاغات، توثيق بائعين، عرض قواعد الرسوم
- مخطط PostgreSQL + RLS + تخزين صور في Supabase

> هذا إصدار تأسيسي. يلزم إنشاء مشروع Supabase وإضافة المفاتيح، ثم الاختبار قبل الإطلاق.

## البنية

```text
nyala-market/
  mobile/          # تطبيق Flutter
  web/             # موقع + لوحة إدارة (Next.js)
  supabase/
    schema.sql               # المخطط الكامل (يشمل الرسوم)
    seed.sql                 # تصنيفات + قواعد رسوم أولية
    fees_migration.sql       # ترحيل لقواعد قديمة
    trust_features_migration.sql
```

## 1) إعداد Supabase

1. أنشئ مشروعاً في https://supabase.com
2. افتح SQL Editor ونفّذ بالترتيب:
   - `supabase/schema.sql`
   - `supabase/seed.sql`
3. إن كان عندك قاعدة قديمة: نفّذ `fees_migration.sql` ثم حدّث البذور إن لزم.
4. من Storage أنشئ bucket باسم `listing-images` واجعله Public.
5. انسخ Project URL و anon key.

## 2) تشغيل الموقع

```bash
cd web
cp .env.example .env.local
# أضف NEXT_PUBLIC_SUPABASE_URL و NEXT_PUBLIC_SUPABASE_ANON_KEY
npm install
npm run dev
```

- الموقع: http://localhost:3000
- لوحة الإدارة: `/admin`
- اجعل المستخدم مشرفاً: `update profiles set role = 'admin' where id = '...';`

### تبويبات لوحة الإدارة

1. **الإعلانات** — نشر / رفض / مباع + عرض حالة الدفع
2. **المدفوعات** — تأكيد دفع نقدي أو إلكتروني + نشر، أو إعفاء
3. **قواعد الرسوم** — عرض الأسعار الحالية حسب القسم والنوع
4. **البلاغات**
5. **البائعون** — توثيق / إلغاء توثيق

## 3) تشغيل تطبيق Android

```bash
cd mobile
cp .env.example .env
# أدخل SUPABASE_URL و SUPABASE_ANON_KEY
flutter pub get
flutter run
```

## 4) النشر

- **الموقع**: ارفع مجلد `web` إلى GitHub واربطه بـ **Vercel** (موصى به لـ Next.js) وأضف متغيرات البيئة.
- GitHub Pages وحده لا يكفي لـ Next.js بسهولة؛ Vercel أو Netlify أفضل.
- **Android**: ابنِ APK ثم انشر عبر Google Play أو وزّع محلياً وفق القوانين.
- راجع سياسات RLS والتخزين قبل الإطلاق العام.

## ملاحظات مهمة قبل الإنتاج

- الإعلان لا يُنشر للعامة إلا بعد تأكيد الدفع (أو الإعفاء) من الإدارة.
- أضف لاحقاً: إشعارات واتساب/SMS، رفع إيصال التحويل، سجل تدقيق للمدفوعات.
- لا تضع `service_role` key في التطبيق أو الموقع.
- حدد سياسة واضحة للرسوم والمدة وطريقة التواصل مع البائع عند الدفع النقدي.

## حالة الإعلان والدفع

```
البائع ينشئ الإعلان
        ↓
status = pending
payment_status = unpaid
        ↓
يدفع نقداً أو يحول إلكترونياً ويتواصل مع الإدارة
        ↓
الإدارة من تبويب "المدفوعات":
  - تأكيد دفع نقدي + نشر
  - أو تأكيد دفع إلكتروني + نشر
  - أو إعفاء + نشر
        ↓
status = active  |  payment_status = paid / waived
```
